## 目标与授权边界

完成本地文档、代码、清单和测试，使匿名低额度完整体验、任意 GitHub（代码托管平台）用户登录增额、个人额度、开放展示、管理员休眠和全局费用成为一个可部署候选。

本计划已获授权执行本地修改和验证，但不授权：

- Publish（正式发布）或创建实际标签；
- 生产部署、Kubernetes（容器编排系统）写入或安全组修改；
- 创建 GitHub OAuth App（GitHub 开放授权应用）或生产 Secret（密钥）；
- 真实模型调用、索引重建或 baseline（基线）晋升；
- 节点重启。

当前已由用户暂存的旧候选直接修改；不创建兼容分支、迁移适配器或保留无人使用的访问模式协议。不暂存或提交本轮新修改。

1. 新增本设计及实施计划。
2. 更新唯一执行依据的 3.0 和 7 节，标记旧 oauth2-proxy（认证代理）与 `private/portfolio` 候选在部署前被替代。
3. 更新 docs（文档）入口，把 2026-07-19 总设计/计划的 Phase 4-5（阶段 4-5）标为历史候选，新文件成为当前入口。
4. 删除仅服务旧候选的访问模式工作流、发布授权、认证代理集成、清单和适配器扩展；保留仍被部署主链使用的发布授权共享代码。

完成条件：仓库当前执行入口只有一套 Task 16-17 设计，搜索旧模式只命中文档历史说明或已完成证据。

## Task 2：应用内身份

1. 安装固定版本 `next-auth@4.24.15`，配置八小时加密会话和 GitHub（代码托管平台）`read:user`。
2. 自定义用户信息映射，只消费 `/user` 返回的数字编号和登录名；不把访问令牌、邮箱、组织或团队写入会话。
3. 新增认证路由以及最小类型扩展。
4. 使用稳定数字编号判断管理员；缺失、非法或未匹配时只作为普通登录用户。
5. 为页面提供登录、登出和管理员入口。

定向测试只覆盖当前风险：最小授权配置、会话字段、数字编号管理员判断和未认证/非管理员接口拒绝；不复制第三方库内部行为。

## Task 3：控制库与模型准入

1. 安装固定版本 `better-sqlite3@12.11.1`，在 PVC（持久卷声明）内自建私有子目录，实现单例数据库连接、WAL（预写日志）、权限检查和最小两表初始 schema（数据结构）。
2. 实现 `normal | interview | sleep` 状态读取、到期解释和管理员事务写入。
3. 实现 HMAC-SHA256（带密钥安全哈希）主体、上海时区日期和账本 35 天清理。
4. 实现单事务产品额度与费用预留、有效 usage（用量）结算、确定未调用时删除预留和不确定状态最大结算。
5. 在 `ask`、`generate`、`fix` 第一次供应商调用前接入准入；`check` 不访问控制库也不要求登录。
6. 把代理修复循环收敛为最多两次修复，并从回答、嵌入和重排调用返回统一的用量事实。
7. 现有短窗口限流保留路由速率和并发值，增加有界惰性 TTL/LRU（生存时间 / 最近最少使用）回收；不恢复旧 128 主体硬拒绝。

数据库或控制状态不确定时模型路由失败关闭且没有内存额度回退。测试覆盖状态转换、额度切换、原子预留/结算和崩溃租约，不穷举等价 SQL（结构化查询语言）语句。

## Task 4：公开体验与管理页

1. 新增 `GET /api/experience`、管理员读写接口及严格同源写入。
2. 页面改为统一公开界面：匿名使用 30 天 7 点体验包，`check` 不扣点，登录后获得独立每日额度。
3. 使用服务端签名 Cookie（浏览器标识）作为匿名额度主体，不保存网络地址或浏览器指纹；复用现有点数和账本，不增加按功能计数表。
4. 实现十分钟当前标签页输入暂存与恢复；匿名点数不足时点击操作进入登录，返回后只恢复输入，不自动调用模型。
5. 实现登录/登出、管理员入口、剩余额度、开放展示/休眠图标和统一错误提示；主页面模式名只在悬停或键盘聚焦时显示。
6. 新增 `/k8s-yaml-assistant/admin` 管理页，只提供普通、开放展示、休眠切换和 1/4/8 小时选择。
7. 页面状态初次读取、60 秒刷新、重新获得焦点刷新和模型请求后刷新复用一个客户端状态模块。
8. 体验状态按 `ask`、`generate`、`fix` 分别表达运行时和点数可用性；Voyage（向量服务）不可用只关闭 `ask`，DeepSeek（回答模型）不可用关闭三项模型操作。

测试聚焦真实边界：匿名令牌签名/到期、匿名与登录账本隔离、输入恢复、状态图标可访问名称及管理授权；不把文案样式或布局细节固化为阻断契约。本阶段不实现回答反馈、点赞/点踩、原因标签或采纳信号。

## Task 5：部署契约

1. 增加独立 1 GiB 控制库 PVC（持久卷声明）、应用挂载和最小环境变量；生产 Secret（密钥）只以引用出现。
2. 保留只读根文件系统既有的 64 MiB 有界 `/tmp` 临时卷，不为控制库增加平行临时存储。
3. 删除 oauth2-proxy（认证代理）和两套模式路由，改为入口控制器直达应用；保留请求中间件和证书候选。
4. 探针恢复旧根路径，新镜像用单次同主机 HTTP `307` 临时重定向连接基础路径健康处理器，锁定 `v0.1.1` 回滚失败关闭行为。
5. 从固定部署适配器和工作流契约删除 `set-access-mode` 及其发布授权面；部署主链仍只接受已发布镜像摘要。

部署测试只断言有风险的资源关系，不复制整份清单。
