# G1 回答反馈第一闭环设计

> 状态：2026-08-02 代码审查问题已完成本地修订、自动门禁和用户交互审核；G1 交付由 PR（合并请求）#40 承载，尚未发布或部署。
> 用途：定义 Ask/Generate/Fix（询问 / 生成 / 修复）成功结果的低敏感反馈、请求关联和管理汇总；不进入 G2（反馈审核候选）或评估回灌。

## 1. 产品契约

三类模型操作的成功结果统一显示拇指向上 / 拇指向下图标，评价对象分别是本次回答、本次生成和本次修复。未选择时显示两个图标；选中后只显示当前图标，再次点击取消并恢复两个图标。数据库只保留当前选择，不保留取消历史。

正反馈点击后立即保存，不要求原因。负反馈先打开原因弹窗，必须选择一个封闭原因后提交。三条路由共享错误或不完整、未满足要求、结果无法使用、响应慢或功能异常、其他；Ask（询问）额外提供依据或引用问题，Fix（修复）额外提供修改无关内容或引入新问题。显示文案按路由表达，底层保留统一原因码。G1 不提供自由文本，避免额外收集敏感 YAML（配置文件）或凭据。

反馈用于管理页按 `ask | generate | fix` 汇总良好/不佳数量，并汇总负反馈原因。G1 不自动创建 bad case（问题用例）、eval case（评估用例）、Holdout（留出集）或 baseline（基线），也不触发模型调用。

## 2. 唯一请求关联

复用控制库 `request_ledger.request_id`，不新增反馈编号或平行身份：

- `reserveModelRequest`（预留模型请求）生成的服务端随机 UUID（通用唯一标识符）同时作为费用账本、Ask 安全观测和反馈关联编号；
- Ask 只在成功完成的 SSE `done`（完成事件）中返回 `requestId`；Generate/Fix 只在成功 JSON（数据交换格式）响应中返回 `requestId`；
- 失败请求不向浏览器提供可反馈编号；
- 浏览器提交服务端编号和当前选择；负反馈额外提交一个封闭原因，取消选择提交 `rating: null`。浏览器不能提交路由、身份、内容、时间或汇总字段；
- 服务端使用当前登录/匿名主体的既有 HMAC（带密钥安全哈希）重新匹配账本主体，未知、过期或属于其他主体的编号统一按目标不存在处理。

UUID 的不可猜测性、当前主体匹配和仅成功响应返回共同限定写入目标。服务端不接受客户端声明的 `ask | generate | fix`，管理汇总从账本中的权威 `route` 读取。

## 3. SQLite v1 → v2

生产控制库已经是 `user_version=1`。初始化逻辑必须保留原 v1 建表事务，再以独立事务迁移到 v2；新库也按 `0 → 1 → 2` 顺序初始化，不能把反馈表塞回 v1 SQL（结构化查询语言）后假装生产尚未存在。

v2 新增：

```sql
CREATE TABLE response_feedback (
  request_id TEXT PRIMARY KEY
    REFERENCES request_ledger(request_id) ON DELETE CASCADE,
  rating TEXT NOT NULL,
  reason TEXT,
  CHECK (
    (rating = 'good' AND reason IS NULL) OR
              (rating = 'bad' AND reason IS NOT NULL AND reason IN (...))
  )
);
```

反馈不复制 `route`、主体哈希、问题、YAML、回答、来源、用户名、OAuth（开放授权）令牌或供应商信息。`request_id` 是主键，`INSERT ... ON CONFLICT DO UPDATE` 只保留当前选择和负反馈原因；取消选择直接删除该行。数据库约束保存全部合法原因的并集，服务端再从账本读取权威 `route` 校验该原因是否适用于目标操作。

账本已完成记录保留 35 天；删除账本时通过外键级联删除反馈，因此反馈保留期同为最多 35 天。Ask 原始安全观测继续使用既有独立存储、采样、脱敏和 7 天保留期；反馈不会延长、复制或阻止观测删除。7 天后反馈可能只剩路由与选择，G2 如需复现材料必须走后续独立设计。

## 4. API 与失败语义

新增 `POST /api/feedback`：

- 只接受同源 `application/json`；
- 复用现有有界请求体读取和严格对象解码，预算 1 KiB；
- 正反馈只接受 `{ requestId, rating: 'good' }`，负反馈必须是 `{ requestId, rating: 'bad', reason }`，取消选择只接受 `{ requestId, rating: null }`；
- 成功回显已保存的当前选择并返回 `Cache-Control: no-store`；
- 未知、过期或主体不匹配返回 404 `feedback_target_not_found`，不暴露目标是否属于其他人；
- 原因属于全局枚举但不适用于账本中的目标路由时返回 400 `invalid_request`；
- 控制库不可用返回 503 `control_state_unavailable`；
- 反馈写入使用严格身份解析；登录会话解析失败不降级为匿名主体，而是沿用 503 控制状态不可用语义。

管理员 `GET /api/admin/experience` 在既有模式状态外增加反馈汇总，一次数据库事务返回 35 天保留窗口内的总计、三条路由计数和负反馈原因计数。管理页是这些字段的直接生产消费者；模式写入响应不重复计算汇总。

## 5. UI

新增一个复用组件，三类成功结果只传入对应 `requestId`：

- Ask 在完整 `done` 事件后出现反馈；流式中途或错误时不出现；
- Generate 在合法结果写入编辑器后出现；
- Fix 在合法修复结果写入编辑器后出现；
- 新的同类请求开始时清除该操作的旧反馈目标；手工编辑 YAML 或执行另一类操作不清除目标，因为评价对象是该次操作是否有帮助，而不是当前编辑器快照；
- 正反馈立即保存，负反馈选择原因并提交后才切换；关闭负反馈弹窗不改变原选择；
- 激活后只显示当前图标，再次点击取消；取消后才显示另一选项，从负反馈改为正反馈时数据库同时移除旧原因；
- 原因使用原生单选语义；弹窗约束键盘焦点并在关闭后返回触发按钮；
- 使用 `aria-pressed` 表达当前反馈选择；反馈控制库不可用时显示反馈保存失败，不宣称模型已关闭。保存错误只在反馈区域显示，不把已成功的模型结果改成失败。

管理页显示“最近 35 天反馈”，包括总计、Ask/Generate/Fix 分项和负反馈原因；不展示用户、请求明细或原始内容。

## 6. 验收

- v1 真实结构夹具事务迁移到 v2，既有模式和账本行保持；迁移冲突时完整回滚且版本不前移；
- 预留中的请求、错误主体、未知和过期请求不能写反馈；
- 完成请求可在 good、带封闭原因的 bad 和无选择之间切换，同一请求最多只计一次；
- Ask/Fix（询问 / 修复）专属原因由账本路由约束，客户端不能声明路由绕过；
- 同一路由不同负反馈原因的分项计数必须累加并与总计一致；
- 35 天清理级联删除反馈，7 天 observation（观测）配置和实现不变；
- Ask 账本、观测和浏览器反馈使用同一 `requestId`；三类失败响应不返回该编号；
- API（应用程序接口）严格拒绝额外字段、非法 UUID、无原因的 bad、带原因的 good / 取消选择和枚举外值；
- 管理汇总、浏览器请求路径、SSE 完成事件、生成结果与反馈编号配对以及三类 UI 消费通过定向测试；
- 完整 `npm test`、类型检查、生产构建及 `git diff --check` 通过。

本地自动验收结果：完整测试 `335/335` 通过，类型检查、生产构建和 `git diff --check` 均通过；构建产物包含 `/api/feedback`。此前无模型预览已覆盖基础图标和负反馈弹窗，2026-08-02 审查后新增的激活态隐藏、操作级文案、路由原因、焦点约束和原生单选交互已由用户审核通过。生产 v1 到 v2 迁移、真实反馈写入以及发布后页面验收仍须在发布部署获得独立授权后执行。
