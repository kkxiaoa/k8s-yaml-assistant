## Q1. 为什么要用向量检索?

**根本约束:不能把整个知识库塞进 prompt。** 太贵、超上下文、稀释注意力。
所以必须每次只挑相关的几段喂进去 —— 这就是"检索"。

为什么是**向量**而不是关键词(grep / BM25)?

| | 关键词检索 | 向量检索 |
|---|---|---|
| 匹配 | **字面**(词要对上) | **语义**(意思接近) |
| 用户问"怎么让 PVC 能扩容?" | ❌ 文档写的是 `allowVolumeExpansion`,无"扩容"二字 | ✅ 二者向量距离近,能命中 |

**本质:把文本映射到一个空间,意思相近的文本距离近。** `cosineSimilarity` 算的就是这个距离。
它跨越了"用户口语 ↔ 文档术语"的鸿沟。

> 但关键词在**字段名 / 错误码 / 专有名词**上更精确 → 生产里常二者混用(见 Q3 hybrid)。

## Q2. demo 很准,实战为什么经常检索错?

因为 demo 是**精心布置的玩具**,实战每个假设都会破:

| demo(准) | 实战(翻车) |
|---|---|
| 7 个片段,主题隔得开 | 几万片段,大量近义/近重复,正确项要和几十个对手竞争 |
| 片段手切,大小=完整语义 | 真实文档切不好:太大→一 chunk 混多主题、向量被"平均"成四不像;太小→语义不完整 |
| 问题用词规范 | 用户口语化、简短、错别字,和术语在向量空间里不近 |
| 答案在单个片段里 | 答案需跨多片段组合,top-k 只捞到一半 |
| 干扰项 0.358 vs 正确 0.752,差距大 | 实战可能 0.71 vs 0.73,一点噪声就把正确项挤出 top-k |

迭代 0 已现苗头:PVC 干扰项 0.358 进了 top-3,只是差距大没造成危害。生产里差距会缩到危险区。

## Q3. RAG 真正的工程难点 + 解法

**核心认知:RAG 调优 80% 在"检索层",不在 prompt / 模型。**

1. **切片(chunking)** —— 最被低估
   - 难点:一个 chunk = 一个完整自洽的语义单元
   - 解法:按结构切(字段/章节/函数,而非固定字数)、控制大小+重叠(overlap)、把标题/层级路径拼进 chunk

2. **召回质量** —— 提升最大处
   - **Hybrid search**:向量 + 关键词 BM25,字段名/版本号用关键词兜底
   - **Rerank(重排)** ⭐ 性价比最高:粗召回 top-50 → cross-encoder 精排 top-5
   - **Query 改写/扩展**:口语问题改写成接近文档的表述,或多 query 变体
   - **元数据过滤**:先按 `resource=StorageClass` 过滤再向量检索,避免跨资源串味

3. **生成约束** —— 防幻觉:强制"只依据 docs"、citation 引用来源、该拒答就拒答

4. **知识更新一致性**:文档变了向量库要同步、版本化

## Q4. 怎么用指标定位是切片 / 检索 / 回答哪层坏了 ⭐

**RAG 是流水线,必须分层评估,否则"它答错了"无法定位。**
前提:一个小标注集(问题 → 标准答案 + 应命中哪些 chunk),哪怕手工 30 条。

| 层 | 指标 | 看什么 |
|---|---|---|
| 检索 | **Recall@k** ⭐ | 正确 chunk 在不在 top-k |
| 检索 | MRR / 命中排名 | 正确 chunk 排得够不够前 |
| 生成 | **Faithfulness** | 回答有没有超出检索内容(幻觉) |
| 生成 | Answer Relevance | 答没答到点 |

**定位故障层的决策树:**

```
1. 先看 Recall@k:标注的"正确 chunk"在 top-k 吗?
   ├─ 不在 → 检索/切片层。把"正确 chunk"手动塞进上下文,模型还答不对时,
   │         再问关键一问:【人】光看这段 chunk 能不能答对?
   │      ├─ 人能答对、只有模型答不对 → 其实是【生成】问题(模型没用好完整信息)
   │      ├─ 人也答不全(chunk 残缺/去上下文/歧义/答案跨多段)→【切片】问题 → 重切
   │      └─ 人能答、模型也能答(塞进去就对了)→ 纯【检索】问题 → hybrid / rerank / query 改写
   └─ 在 top-k → chunk 给对了还错 →【生成】问题 → 改 prompt 约束 / citation / 换模型
```

> ⚠️ 注意"正确 chunk"的歧义:它指**标注集里标的"应命中那段"**,不等于"这段真的完整自洽地装下了答案"。
> 切片差时,这段被切碎/去掉标题/只含半个答案 → 塞进去人也答不全 → 那是**切片**的锅,不是模型的。
> **判别钥匙就是那一问:「人光看这段 chunk 能不能答对?」** 它把"信息在不在 chunk 里"和"模型会不会用"分开。

一句话:**先用 Recall@k 切开"检索 vs 生成",再用"塞进正确 chunk + 问人能否答对"切开"切片 vs 生成 vs 检索"。**
对接 Notion 指标桩:答非所问率→检索层,一次通过率/幻觉率→生成层。
